# Глоссарий

Термины и как именно они употребляются в этом проекте.

| Термин | Значение здесь |
|---|---|
| **Трек 3** | направление хакатона на данных Минтранса и Яндекса. Наш. |
| **Idea Freeze** | момент конца 2-го дня, после которого концепция решения заморожена (Регламент п. 5.10–5.12). |
| **Покрытие** | доля жителей, у которых остановка в пешей доступности. Главная метрика продукта. |
| **Изохрона** | зона, достижимая пешком за N минут от точки. В `stations.csv` изохроны по остановкам уже посчитаны Яндексом. |
| **Пешая доступность** | попадание жилой ячейки в изохрону остановки. Порог (5/10/15 мин) — параметр, не константа. |
| **Дыра в покрытии** | область с высокой плотностью населения и без остановки в пешей доступности. То, вокруг чего строятся сценарии. |
| **Сценарий** | изменение сети, которое пользователь задаёт в песочнице: продлить маршрут, добавить остановку, снять дублирование, изменить число машин. |
| **Дельта** | разница метрик «до» и «после» сценария. Ответ инструмента — всегда дельта, а не абсолют. |
| **OD-матрица** (матрица корреспонденций) | сколько поездок из зоны A в зону B. Для Ташкента не существует; выдана только по Олмалику (55 зон, модельная). |
| **TAZ** | transport analysis zone, транспортный район — единица зонирования для OD. Официальных TAZ Ташкента в открытом доступе нет. |
| **tap-in only** | система оплаты регистрирует только вход. Выход не фиксируется → назначение поездки напрямую неизвестно. Так работает Ташкент. |
| **trip-chaining** | метод восстановления точки высадки: следующая транзакция той же карты даёт зону выхода из предыдущей поездки. Мировая точность 66–80% по остановке. |
| **Карто-день** | пара (карта, дата). Единица для оценки, сколько людей делают >1 поездки в день. |
| **Пересадка** | отдельная транзакция той же поездки, размечена тарифом («Пересадка 0/700/1100»), 5.72% строк. Транзакция ≠ пассажир. |
| **Брутто-контракт** | схема, где город платит перевозчику за пройденный путь и «качество», а выручка идёт городу. 279 маршрутов, ~2 трлн сум/год. |
| **QATNOV** | название продукта. Цифровой двойник маршрутной сети Ташкента, рабочее место специалиста по сети. |
| **ПП-59** | постановление от 16.02.2023 о реформе городского транспорта; п. 3(а) предписывал внедрить новую сеть автобусных маршрутов в Ташкенте **до 1 марта 2023**. Не исполнено — стартовая точка проблемы. Даты «1 мая 2023» в постановлении нет. |
| **H3 r8** | гексагональная сетка Uber, разрешение 8 (гексагон ~0.74 км²). Базовая расчётная единица проекта. |
| **Kontur Population** | открытый слой населения в H3 r8, собран из GHSL + контуров зданий Microsoft/Meta + OSM. Лицензия CC BY → строка атрибуции в подвале обязательна. |
| **СНиП 2.07.01-89** | норматив, из которого взят порог пешей доступности остановки — **500 м** по пешеходной сети. |
| **People Near Transit** | методика оценки доступа: считаются люди рядом с маршрутами с интервалом **до 15 минут**, а не рядом с любой остановкой. |
| **PTV Visum** | пакет транспортного моделирования, на котором считают Минтранс и ТАДИ. Формат под него = аргумент «внедряемо». |
| **STEP City** | подрядчик транспортного мастер-плана и макромодели Ташкента до 2045, сдача — конец сентября 2026. |
| **GTFS** | стандартный формат данных общественного транспорта. В Узбекистане не опубликовано ни одного фида. |
| **IVMS** | диспетчерская система, которой сейчас меряют работу перевозчика — по GPS, то есть по предложению, а не по спросу. |
| **`dept_num`** | поле транзакции; для метро содержит станцию (`Чилонзор-1` → `Чилонзор`), а не `station`. |
| **`pan_hash` / `masked_pan`** | псевдонимизированные идентификаторы карт. Связывать с реальными людьми запрещено условиями трека. |
| **Остановка-призрак** | строка в `stations.csv` с `route_count = 0` и пустым `transport_types`: остановка есть, обслуживания нет. Таких 197. |
| **Обслуживаемая остановка** | остановка с `route_count > 0`. Только они дают покрытие: покрытие по всем физическим остановкам делает прирост от продления маршрута структурно невозможным. Их 2 675 из 3 422. |
| **PNT-500** | сумма населения гексагонов, до которых от обслуживаемой остановки доходит пешком за 500 м **по сети улиц**. Наш результат — 2 362 141 (90.4%). |
| **PNFT-15** | то же, но остановка засчитывается, только если хотя бы один её маршрут ходит с интервалом ≤ 15 мин в этот час. 1 475 301 (56.5%), и это нижняя оценка. |
| **T-median** | медиана времени пешком до ближайшей остановки, взвешенная по населению. 3.25 мин. Меряется медианой по вершинам гексагона: минимум вырождается в ноль. |
| **`quality = exact / approximate`** | восстановлен ли порядок остановок маршрута. `exact` — 60 маршрутов, у них есть геометрия и расписание. `approximate` — остальные, лежат в базе без геометрии, догадками не достраиваются. |
| **`source = traffic / fallback`** | чем посчитано время хода по перегону: скоростью реальной точки наблюдения Яндекса или медианой по городу за тот же час. 91.1% строк — `traffic`. Показывается в интерфейсе как честность расчёта. |
| **Дыра покрытия** | гексагон с населением, до которого нет обслуживаемой остановки в 500 м. 217 штук, 251 079 человек. |
| **`k` и `n` на перегоне** | порядковый номер маршрута на перегоне и сколько их всего — фронт разводит по ним параллельные линии в пикселях. До 9 маршрутов на одном перегоне. |
